# HurraS2SSDK

A Swift package for iOS applications that enables server-to-server (S2S) tracking of user events and views.

## Overview

HurraS2SSDK provides a simple interface for sending event data to Hurra's analytics backend while respecting user privacy preferences. It supports tracking page views, user interactions, and custom events with minimal setup.

## Documentation

- [Privacy Preferences API Documentation](PrivacyPrefsAPI.md) - Detailed documentation for managing user privacy preferences and consent settings

## Installation

### Swift Package Manager

Add the package to your `Package.swift`:

```swift
dependencies: [
    .package(url: "https://github.com/hurra-com/OWAPro-iOS-SDK.git", from: "1.1.2")
]
```

Or add it directly in Xcode:
1. File > Add Packages...
2. Enter the repository URL: `https://github.com/hurra-com/OWAPro-iOS-SDK.git`
3. Select the version you want to use

## Configuration

Initialize the SDK with your account credentials:

```swift
import HurraS2SSDK

// use user ID generated by SDK
let hurraSDK = HurraS2SSDK(
    accountId: "your_account_id",
    apiKey: "your_api_key"
)

// Or use IDFA for user identification
let hurraSDK = HurraS2SSDK(
    accountId: "your_account_id",
    apiKey: "your_api_key",
    useAdvertiserId: true  // Use IDFA if available
)

// Or use user ID managed by app
let hurraSDK = HurraS2SSDK(
    accountId: "your_account_id",
    apiKey: "your_api_key",
    customUserId: nil       // Provide a custom user ID if needed
)

// Or send requests through your own domain (see below)
let hurraSDK = HurraS2SSDK(
    accountId: "your_account_id",
    apiKey: "your_api_key",
    baseURL: URL(string: "https://www.example.com/hc_s2s")!
)
```

### Sending requests through your own domain

By default the SDK sends its requests to `https://s2s.hurra.com`. You can send them through your own domain instead, with a reverse proxy that forwards them to `https://s2s.hurra.com/`. The app then talks to your domain, not to a third-party tracking domain.

Pass the same `baseURL` to `HurraS2SSDK` and to `PrivacyPrefsAPI`:

```swift
let baseURL = URL(string: "https://www.example.com/hc_s2s")!

let hurraSDK = HurraS2SSDK(
    accountId: "your_account_id",
    apiKey: "your_api_key",
    baseURL: baseURL
)

let api = await PrivacyPrefsAPI(
    accountId: "your_account_id",
    apiKey: "your_api_key",
    userId: hurraSDK.getUserId() ?? "",
    baseURL: baseURL
)
```

- `baseURL` must be an `https` URL with a host and without query or fragment; the SDK stops with a precondition failure otherwise. A trailing slash is optional.
- Default: `HurraS2SSDK.defaultBaseURL` (`https://s2s.hurra.com`).

The proxy must forward these paths below the base URL to `https://s2s.hurra.com/`, with method, query string, headers and body unchanged:

| Path | Used by |
|------|---------|
| `/rt` | event and view tracking (`HurraS2SSDK`) |
| `/consent-api/…` | consent API (`PrivacyPrefsAPI`) |

and add these headers:

| Header | Value |
|--------|-------|
| `X-Hurra-Client-IP` | IP address of the app user (the client that connected to the proxy) |
| `X-Hurra-Proxy-Domain` | your domain, e.g. `www.example.com` |
| `X-Hurra-Proxy-Path` | the path of the base URL, e.g. `/hc_s2s` |

Example for nginx, for the base URL `https://www.example.com/hc_s2s`:

```nginx
location /hc_s2s/ {
    proxy_pass https://s2s.hurra.com/;
    proxy_set_header X-Hurra-Client-IP $remote_addr;
    proxy_set_header X-Hurra-Proxy-Domain $host;
    proxy_set_header X-Hurra-Proxy-Path "/hc_s2s";
    proxy_set_header X-Forwarded-For $remote_addr;
    proxy_connect_timeout 10s;
}
```

### Storing API Credentials

For security, store your API credentials outside of your source code:

#### Option 1: Using Info.plist

Add to your app's Info.plist:

```xml
<key>HurraAPICredentials</key>
<dict>
    <key>AccountId</key>
    <string>your_account_id</string>
    <key>ApiKey</key>
    <string>your_api_key</string>
</dict>
```

#### Option 2: Using Environment Variables

Set environment variables:

```bash
export HURRA_ACCOUNT_ID=your_account_id
export HURRA_API_KEY=your_api_key
```

## Usage

### Tracking Views

```swift
// Basic page view tracking
Task {
    await hurraSDK.trackView(
        eventData: [
            "page_type": "product_detail",
            "product_id": "12345",
            "category": "electronics"
        ],
        currentView: "https://example.com/products/12345"
    )
}
```

### Tracking Events

```swift
// Track user interactions
Task {
    await hurraSDK.trackEvent(
        eventType: "add_to_cart",
        eventData: [
            "product_id": "12345",
            "price": "99.99",
            "currency": "USD",
            "quantity": 1
        ],
        currentView: "https://example.com/products/12345"
    )
}

// With completion handler
Task {
    await hurraSDK.trackEvent(
        eventType: "purchase",
        eventData: [
            "order_id": "ORD-12345",
            "total": "99.99"
        ],
        currentView: "https://example.com/checkout/confirmation",
        isInteractive: true
    ) { result in
        switch result {
        case .success(let response):
            print("Event tracked successfully: \(response)")
        case .failure(let error):
            print("Failed to track event: \(error)")
        }
    }
}
```

### Tracking Page Views from Deep Links

When your app is opened via a registered URL (a custom URL scheme or a universal link), track a page view and copy every query string parameter from the incoming URL onto `currentView`'s query string, so attribution data (campaign, referral, etc.) carried by the deep link is preserved in the event:

```swift
import HurraS2SSDK

class AppDelegate: NSObject, UIApplicationDelegate {
    @MainActor let hurraSDK = HurraS2SSDK(
        accountId: "your_account_id",
        apiKey: "your_api_key"
    )

    func application(
        _ app: UIApplication,
        open url: URL,
        options: [UIApplication.OpenURLOptionsKey: Any] = [:]
    ) -> Bool {
        Task {
            await trackDeepLinkPageView(from: url)
        }
        return true
    }

    @MainActor
    func trackDeepLinkPageView(from url: URL) async {
        // The view associated with the deep link's path, e.g. "product_detail".
        var components = URLComponents()
        components.scheme = "https"
        components.host = "example.com"
        components.path = url.path

        // Copy all query string parameters from the opening URL onto currentView.
        components.queryItems = URLComponents(url: url, resolvingAgainstBaseURL: false)?.queryItems

        let currentView = components.url?.absoluteString ?? url.absoluteString

        await hurraSDK.trackView(
            eventData: ["page_type": "deep_link"],
            currentView: currentView
        )
    }
}
```

The same pattern works with SwiftUI's `.onOpenURL`:

```swift
ContentView()
    .onOpenURL { url in
        Task {
            await hurraSDK.trackDeepLinkPageView(from: url)
        }
    }
```

### Managing Privacy Preferences

```swift
// Create privacy preferences
let privacyPrefs = PrivacyPrefs()

// Set all categories
privacyPrefs.setAllCategories(true)

// Or set specific categories
privacyPrefs.setCategory(.essential, accept: true)
privacyPrefs.setCategory(.analytics, accept: true)
privacyPrefs.setCategory(.functional, accept: false)
privacyPrefs.setCategory(.advertisement, accept: false)
privacyPrefs.setCategory(.personalization, accept: false)

// Apply preferences to the SDK
hurraSDK.setPrivacyPrefs(privacyPrefs)
```


## Response Format

The SDK returns a `ServerResponse` object with the following structure:

```swift
public struct ServerResponse: Codable {
    public let status: Int
    public let error: [String]?
}
```

- `status`: 1 for success, 0 for accepted but not processed, negative values for errors
- `error`: Optional list of error messages from the server

## Thread Safety

The SDK is designed to be thread-safe with `@MainActor` annotations on its public methods. Always call SDK methods from the main thread or use `Task` with `await` to ensure proper execution.

## Privacy Considerations

- The SDK respects user privacy preferences set through the `PrivacyPrefs` class
- By default, it uses a generated UUID for user identification
- IDFA (Advertiser ID) usage is optional and requires user permission
- All data is sent securely over HTTPS

## App Tracking Transparency

### Rule

- Requests to the default domain `s2s.hurra.com` are sent only when the user has granted App Tracking Transparency (ATT) permission (`ATTrackingManager.trackingAuthorizationStatus == .authorized`). This can't be switched off.
- Requests to your own domain (`baseURL`, see "Sending requests through your own domain"): you decide with `requiresTrackingAuthorization` (default `true`).
- Without the required permission, `sendEvent`, `trackEvent` and `trackView` don't send anything and call the completion with `S2SError.trackingNotAuthorized`. An event that isn't sent doesn't become the `referer` of the next event.
- `PrivacyPrefsAPI` (consent API) doesn't check ATT: it is needed to show the consent screen.
- Consent outside the OS (`PrivacyPrefs`, categories c0–c4) is unchanged and stays your responsibility.

```swift
// Your own domain, measurement that isn't tracking in Apple's sense
let hurraSDK = HurraS2SSDK(
    accountId: "your_account_id",
    apiKey: "your_api_key",
    baseURL: URL(string: "https://www.example.com/hc_s2s")!,
    requiresTrackingAuthorization: false
)
```

### The prompt is shown by the app

The SDK never shows the ATT prompt; it only checks the status. If ATT permission is required, the app asks for it with `ATTrackingManager.requestTrackingAuthorization` and needs its own `NSUserTrackingUsageDescription` in `Info.plist`.

### Privacy manifest

The SDK's `PrivacyInfo.xcprivacy` declares the minimum: `NSPrivacyTracking = false`, no tracking domains, and the collected data types (Device ID, User ID, Product Interaction) as linked to the user but not used for tracking. The app can't remove what an SDK declares, so this leaves the decision to you.

If you consider your measurement tracking in Apple's sense (linking data from your app with data from other companies' apps, websites or offline sources for targeted advertising or advertising measurement), the app:

- declares `NSPrivacyTracking = true` and the data types with `NSPrivacyCollectedDataTypeTracking = true` in its **own** privacy manifest,
- asks for ATT permission and keeps `requiresTrackingAuthorization = true`.

Whether it is tracking is your (legal) decision.

> [!WARNING]
> Never list your own proxy domain in `NSPrivacyTrackingDomains`. iOS blocks all requests to the domains listed there while ATT permission isn't granted, including the app's own API if it uses the same domain.

### IDFA

With `useAdvertiserId: true`, the IDFA is all zeros without ATT permission. This is how iOS behaves; the SDK doesn't change it.
